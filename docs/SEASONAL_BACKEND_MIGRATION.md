# Backend migration for 21-day anime seasons

**Source review at commit `273a039`.** The findings below come from the Python services and routers, Rust engine and bindings, Lua commits, database models and migrations. The routes and payloads marked proposed are a contract for implementation. This review covers the seasonal feature path. It did not run the server, migrations, tests or model calls.

## Implemented first slice

Run `alembic upgrade head` before deploying the new API. An administrator uses the existing `POST /api/v1/admin/seasons` with `pack_key` set to `grimoire-awakening-v1` or `skybound-voyage-v1` and a 21-day UTC window. The window must start at midnight UTC. Existing seasons without a pack continue through the existing progression endpoints. The new public manifest returns null if the active window has no published pack. Each player can read and save their current season character through the authenticated GET and PUT routes at `/api/v1/seasons/{season_id}/me/character`.

Both packs use original demo characters and the existing frontend GLBs for previews. The first slice covers the public cast and authenticated selection. Story duels permit a single public Strike call, submitted atomically with a legal lead. Moves, hints, and versioned retries reuse the practice API. Signed-in story duels persist in PostgreSQL. Guest and shared duels use the practice retention policy.

The opening story escape awards 20 coins and 40 season points once per player and season. The result screen confirms this with the account and attempt credentials. A player who clears the opening duel, selects a character and reaches 300 season points can unlock that character's final form. Packed seasons use three seven-day buckets and a three-day awakening claim window after close. Older seasons retain calendar-week progression.

## Story AI and approved dialogue

The story result links to a read-only coach that requires the finished attempt capability. It rescores the rival's first choice with at least two legal cards and returns the played card, candidate count and estimated escape rates. A rules question retrieves a curated citation or abstains. The optional adaptive rival asks Gemini for one of two intents before dealing. An unavailable or slow model falls back to the stable Rust policy.

The awakening coach resolves a versioned prerequisite graph against one account-scoped PostgreSQL read. It returns the path, step states, fact references and claim deadline without a model call. An authenticated lookup surfaces an earned final form during the three-day claim window after close. The MCP server offers the public requirement graph for tooling without exposing account progress. [Prerequisite graph](../app/modules/story/awakening.py) · [HTTP contract](api/README.md)

In the admin console, **Season cues** creates a draft for a pack, character and Strike or victory scene. Each advance invokes the LangGraph generation node for one language and stores its result in PostgreSQL. An editor can correct the pair and publish it. The existing voice worker renders approved lines, and public playback prefers English, then Japanese with English captions. A missing clip can be queued again after cache expiry. The authored fallback pair lets the workflow finish without a provider. The Gemini context benchmark compares repeated public season prompts sent inline or through explicit caching. Run it with a configured key before deciding whether to use explicit caching in production. [Benchmark instructions](AI.md#gemini-context-cache-benchmark)

Check the active player is the eligible leader after the opening trick and still has a call. Commit once under the current connection, version and deadline. A declaration preserves the turn owner and existing deadline. Resolve success on the caller's Strike against the named recipient, or close on a wrong recipient, escape, game end or two resolved tricks. Append the declaration and its resolution to the ordered stream, and include pending call state in private resync. Identical retries return the recorded acknowledgement. Test declaration versus simultaneous lead, timeout and reconnect. Introduce a season rival profile and pre-hand Gemini intent using only permitted seat observations and public prior outcomes. Rust validates the candidate and plays on deadline even during a provider outage. Store the intent, policy version and accepted action. Calibrate a target rival rating of 1.05 × player rating with seeded simulations before promising difficulty. Archive exceptional-play evidence from assessed multi-option decisions and use it to trigger the equipped emote. All paths below are **proposals** relative to `/api/v1`. Preserve the current player-scoped season, practice, store, ticket and participant replay endpoints during rollout.

| Interface | Access and minimum payload |
| --- | --- |
| GET /seasons/active/manifest | Public published content or an explicit off-season response. Season ID, anime ID, version, UTC dates, acts, cast, encounter IDs, hashed assets, animation slots and caption/clip references. |

## Online rollover and result receipts

Apply migration `20261127_match_receipts` before starting the upgraded API and game workers. Replace older live-state writers and the older admin close handler before enabling new admissions. Existing live matches and archived replays remain readable.

Admission uses the Redis clock and a shared PostgreSQL schedule lock. The Redis transition rechecks the cutoff. Closing a season waits for its active and unsettled matches. When a match finishes after its season closes to new admissions, progression uses that season's last eligible UTC day. Global daily coin limits use the actual completion date. Matches admitted between seasons have no season award, and matches that predate admission metadata use the original finish-time lookup.

The participant result endpoint distinguishes in-progress, pending and settled results. The replay and receipt commit with coins, season points, bank coins and the MMR change in one transaction. The receipts are stable across settlement retries and can reopen from **Progress → Recent matches**. For older archives the service returns the recorded placement with unavailable reward amounts. ## Season rewards inbox and squad finale

Apply migration `20261127_season_squads` before starting the upgraded API. Progress shows earned tiers, streak bonuses and completed act challenges for the active packed season and the past season during its grace period. Weekly claims accept the act's UTC start date, and omitted dates default to the current or final act. Each historical act claim keeps its original ledger key. Legacy seasons retain the current-week claim behavior. Earned cosmetics appear in the store as owned items and use the existing equip route.

In Friends, the leader enrolls two to four active members of the current party. PostgreSQL freezes their roster and keeps it after party changes. Each player can join one squad per season. Every member who escapes a story duel started after enrollment contributes once. The story attempt records the enrollment at admission, and its authenticated settlement records the clear. Squad progress exposes each viewer's own contribution and the aggregate count. When the squad completes, each roster member can claim 60 coins and a Squad Finale frame. Claim writes and retries use the same wallet ledger key and cosmetic ownership entry. [Squad rules](../app/modules/progression/squad.py) · [HTTP API](api/README.md)

## Story campaign and attempt recovery

Apply migration `20261127_story_campaign` before starting the upgraded API and scheduled maintenance worker. Each published pack has an opening trial, a rivalry duel on day 8, and a finale on day 15 UTC. Later acts require sign-in and the preceding chapter clear. Earlier chapters remain playable through the active season. The opening first-clear amount and historical clear records carry forward. Acts 2 and 3 add their own first-clear grants. Share links pin the chapter, and links issued before this change default to the opening trial. [Campaign definitions](../app/modules/story/chapters.py)

Signed-in attempts persist the pinned chapter, character, rival policy, private engine snapshot and accepted commands. The API commits each move and its retry response together under a row lock. The owner can reopen the latest unexpired attempt from Home after reauthenticating. Incomplete duels use the configured practice lifetime. A completed duel stays available for one day, and an unclaimed result can reopen through the same resume route. Claiming the result stores its receipt with the progression writes. The scheduled cleanup removes expired attempts and their command history. [Attempt storage](../app/modules/game/story_store.py) · [HTTP API](api/README.md)

## Season emotes and standout Strike reviews

Apply migration `20261127_story_emotes` before starting the upgraded API. The season loadout projects options from the account's owned cosmetics. Players can equip the two store emotes, the current season's tier emote or its streak emote after acquisition. Sending a null SKU restores the standard celebration. Story admission pins the emote alongside the character and chapter. Older saved attempts and guest challenges use the standard celebration. [Loadout service](../app/modules/progression/emotes.py) · [HTTP API](api/README.md)

A signed-in, finished duel can return one highlight for a confirmed called Strike with multiple legal choices. The native evaluator uses 768 iterations and requires at least 16 samples for the played card and a comparison. The played card must estimate at least an 80% chance to avoid the Donkey, be within five percentage points of the best adequately sampled move, and outperform one adequately sampled alternative by at least 12 percentage points. The owner receives the estimates, sample counts and pinned emote. The persisted review, including an abstention, is reused after retries. It needs no Gemini request and leaves the reward and next-turn paths independent. [Review policy](../app/modules/story/highlights.py)
