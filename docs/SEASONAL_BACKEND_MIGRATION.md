# Backend migration for 21-day anime seasons

**Source review at commit `273a039`.** The findings below come from the Python services and routers, Rust engine and bindings, Lua commits, database models and migrations. The routes and payloads marked proposed are a contract for implementation. This review covers the seasonal feature path. It did not run the server, migrations, tests or model calls.

## Implemented first slice

Run `alembic upgrade head` before deploying the new API. An administrator uses the existing `POST /api/v1/admin/seasons` with `pack_key` set to `grimoire-awakening-v1` or `skybound-voyage-v1` and a 21-day UTC window. The window must start at midnight UTC. Existing seasons without a pack continue through the existing progression endpoints. The new public manifest returns null if the active window has no published pack. Each player can read and save their current season character through the authenticated GET and PUT routes at `/api/v1/seasons/{season_id}/me/character`.

Both packs use original demo characters and the existing frontend GLBs for previews. The first slice covers the public cast and authenticated selection. The story slice adds an authored seeded duel per pack and permits a single public Strike call, submitted atomically with a legal lead. Ordinary moves, hints, and versioned retries reuse the practice API. Story sessions are process-local and expire under the practice retention policy.

The progression slice adds a first escape receipt worth 20 coins and 40 season points, awarded once per player and season. The result screen confirms it with the account and attempt credentials. A player who cleared the duel, selected a character and reached 300 season points can unlock that character's final form. Packed seasons use three seven-day buckets and keep a three-day awakening claim window after close. Older seasons retain calendar-week progression. The remaining sections include future contracts for story persistence, broader match settlement and audio assets.

## Story AI and approved dialogue

The story result links to a read-only coach that requires the finished attempt capability. It rescores the rival's first choice with at least two legal cards and returns the played card, candidate count and estimated escape rates. A rules question retrieves a curated citation or abstains. The optional adaptive rival asks Gemini for one of two intents before dealing. An unavailable or slow model falls back to the stable Rust policy. Awakening progress names the missing character selection, clear and points requirements.

In the admin console, **Season cues** creates a draft for a pack, character and Strike or victory scene. Each advance invokes the LangGraph generation node for one language and stores its result in PostgreSQL. An editor can correct the pair and publish it. The existing voice worker renders approved lines, and public playback prefers English, then Japanese with English captions. A missing clip can be queued again after cache expiry. The authored fallback pair lets the workflow finish without a provider. Native prompt-cache comparisons, a full KAG graph and inter-agent localization remain planned.

## 2. Featured duel, rival and replay

- **Start a story encounter.** Guest practice uses an expiring in-process session. The lobby offers classic and ranked. Online room start constructs an ordinary game, but the Rust binding already exposes `OnlineGame.seeded` and snapshot restore. Add a dedicated story admission service that resolves a published encounter, seed, rules and rival policy on the server. A signed-in attempt can earn a first-clear reward. A guest can play a sample. A stable rival decision seed must use the encounter version and decision index for challenges that promise identical conditions. - **Deliver a Strike.** Rust emits `Vettu` with cutter, receiver and pile. Commentary, analytics and achievement IDs consume that history. Expose Strike in new text and retrieval aliases first. Normalize the legacy event at presentation boundaries. Keep earned IDs such as `vettu_master` stable. Version any eventual wire rename and count one objective per source event. [Rust events](../engine/core/src/game.rs) · [Analytics](../app/modules/progression/analytics.py) · [Commentary](../app/modules/ai/commentary.py)
- **Call a Strike.** The socket command union supports play, leave, ping, emote and chat. Add a featured-duel-only declaration with target seat, expected version and request ID. Check the active player is the eligible leader after the opening trick and still has a call. Commit once under the current connection, version and deadline. A declaration preserves the turn owner and existing deadline. Resolve success on the caller's Strike against the named recipient, or close on a wrong recipient, escape, game end or two resolved tricks. Append the declaration and its resolution to the ordered stream, and include pending call state in private resync. Identical retries return the recorded acknowledgement. Test declaration versus simultaneous lead, timeout and reconnect. [Socket dispatch](../app/modules/matches/router.py) · [Match state and sync models](../app/modules/matches/schemas.py) · [Atomic commit](../app/modules/matches/game.lua)
- **Let Gemini compete in story mode.** The current bot uses MMR thresholds, deterministic search and a persona choice among well-sampled near-best legal moves. Its 0.05 tolerance is a move safety margin. Rivals record player/bot results. Introduce a season rival profile and pre-hand Gemini intent using only permitted seat observations and public prior outcomes. Rust validates the candidate and plays on deadline even during a provider outage. Store the intent, policy version and accepted action. Calibrate a target rival rating of 1.05 × player rating with seeded simulations before promising difficulty. Archive exceptional-play evidence from assessed multi-option decisions and use it to trigger the equipped emote. [Bot choices](../app/modules/matches/bots.py) · [Rival history](../app/modules/ai/rivals.py) · [Decision analysis](../app/modules/ai/coaching.py)
- **Finish, share and replay.** A persisted match embeds a private opening snapshot. Replay reads require a participant and the public response omits the opening. Keep those controls. A signed share card identifies an authored encounter, version, branch point and rival policy. A friend starts a fresh attempt. Never embed a live deal seed or private hands in a public share. Return a separate settled result with mode-specific placement, eligible cinematic, progression receipt and pending status. Persist optional cosmetic cues or their deterministic manifest references so old wins play consistently. Existing parties and room links can support invitations. Squad finale credit needs durable membership-at-contribution and a unique trial completion key. ## 4. Frontend handoff

All paths below are **proposals** relative to `/api/v1`. Preserve the current player-scoped season, practice, store, ticket and participant replay endpoints during rollout.

| Interface | Access and minimum payload |
| --- | --- |
| GET /seasons/active/manifest | Public published content or an explicit off-season response. Season ID, anime ID, version, UTC dates, acts, cast, encounter IDs, hashed assets, animation slots and caption/clip references. |
| PUT /seasons/{id}/me/character | Player selects an available character. Return effective selection, equipped emote/form, ownership and whether the final-form choice is locked. |
| POST /story/attempts | Encounter ID plus idempotency key. Return scoped attempt credentials, pinned versions, seat, allowed actions and initial view. Define a guest credential with read/play scope for the demo. |
| Featured socket command declare_strike | Accept request ID, expected version and target seat. Publish ordered declaration/outcome events and include outstanding window in sync. Existing card-play commands continue to work. |
| GET /games/{id}/result and POST /seasons/{id}/objectives/{key}/claim | Participant result or pending. Grant receipt identifies season, character, items and coin delta. Retried claims recover the original receipt. |
| POST /story/attempts/{id}/share and GET /challenges/{code} | Create an authorized public curated challenge. Return only an encounter descriptor suitable for starting a fresh attempt. |
| Season cue and coach extensions | Resolve clip, spoken locale, English caption, speaker and clip version by cue. Coach response includes source list with authorized rule or replay references. |

## Shared story challenge and mobile release

A finished story attempt can issue a signed 30-day challenge after checking the attempt capability. The share carries only the versioned setting, character, rival policy and public result summary. A recipient starts a fresh guest attempt at the same opening and can compare results. Links stay usable after season rollover while the corresponding authored pack and signing key remain available. No season or ranked rewards are attached to shared replays.

New room invites use the website query route. Existing `/join/{code}` bookmarks still serve a browser landing page. The approved frontend shell now uses browser layout, controls and a rules dialog with CSS, and its lockfile omits the native compatibility dependency. Host the frontend and forward `/api/v1` with WebSocket upgrades on the same origin. Provision a 21-day pack through the admin API for the story demo. Physical-device rendering and audio measurements remain release checks.
